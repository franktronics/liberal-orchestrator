# Agent Guidelines for Liberal Orchestrator


## Language

CRITICAL: All code, documentation, and comments must always be in English,
even when discussing in French with the user.

## External File Loading

CRITICAL: When you encounter a file reference (e.g. @rules/general.md), use your Read tool to load it on a need-to-know basis. They're relevant to the SPECIFIC task at hand.

Instructions:

- Do NOT preemptively load all references - use lazy loading based on actual need
- When loaded, treat content as mandatory instructions that override defaults
- Follow references recursively when needed

Load the relevant doc file based on the task at hand:

- [app-design](.agents/doc/DESIGN.md): Product, concepts, settled decisions, roadmap
- [architecture](.agents/doc/ARCHITECTURE.md): Pipeline, modules, config layering & scopes, write formats, tests
- [plan](.agents/doc/PLAN.md): v0.1 plan — settled decisions, phases, acceptance criteria, definition of done
- [README](README.md): Project overview, current scope, and local testing instructions

* Always update documentation for significant changes or new features, and remove outdated information.
* Use the format: `[link-name](link): shot description`
* Write documentation only for those features that the code itself cannot describe simply.
* All documentation files must be listed here.
* Prefers short, concise documentation

## Repo layout

- `.agents/` contains ONLY the docs and skills useful for building the
  tool. The tool's own elements (`src/`, `templates/`, `tests/`, `scripts/`)
  live at the package root.
- Artifacts generated by lior (`.codex/`, `.opencode/`, orchestration
  skills) belong to target projects, never to this repo.

## Project quick facts

- `lior` CLI: TypeScript + Bun (ESM, Node ≥ 20 compatible).
- Commands: `bun install`, `bun test`, `bun run lior --help`, `bun run lint` (Biome).
- Style: strict TypeScript; small pure modules; FS side effects confined to
  `src/util/io.ts` and adapter writers; `*.test.ts` tests next to the code;
  golden fixtures in `tests/fixtures/`.
